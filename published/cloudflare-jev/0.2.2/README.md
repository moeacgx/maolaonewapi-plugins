# Cloudflare Jev 任务插件 0.2.2

## 问题与方案

0.2.1 在原生路由解码时只接受 `typesafe/jev`，宿主随后也会检查解码模型属于插件声明。
因此客户端使用 `Typesafe-jev` 时，尚未进入渠道重定向就返回 HTTP 400 / `Invalid request`。
`Typesafe-jev → typesafe/jev` 的渠道配置本身没有错误。

0.2.2 明确声明 `typesafe/jev` 和 `Typesafe-jev`。解码及请求规范化保留客户端原名，
宿主按该名称检查令牌权限、选择渠道和读取价格；发送供应商请求时严格校验映射后
模型为 `typesafe/jev`，Cloudflare 请求仍为 `{model:"typesafe/jev",input:{state,questions}}`。

## 配置与兼容

- 客户端保持 `POST /v1/systemone`。
- 使用别名时，渠道公开模型、重定向键、客户端请求、令牌模型权限及价格键都填写
  精确的 `Typesafe-jev`；重定向值为 `typesafe/jev`。
- 规范名 `typesafe/jev` 保持兼容，不需要额外重定向。
- 这不是任意别名支持。小写横杠名 `typesafe-jev` 不在名单中；宿主禁止在同一插件
  同时声明仅大小写不同的模型，因此不能将其和 `Typesafe-jev` 一起注册。
- 兼容 `.335` 宿主，不修改主程序、模型权限或价格。旧版本源码及 hash 保持不变。
- 完成市场安装后须激活新版本；多节点须刷新插件运行时或按既有发布流程逐节点重启。
- 按次价格与输入用量表达式都按客户端模型名读取；本插件不设定售价。

Cloudflare 账户地址、授权与使用限制沿用 [0.2.0 文档](../0.2.0/README.md)，
Completed 响应解析沿用 [0.2.1 文档](../0.2.1/README.md)。

## 验证计划

在旧插件复现别名拒绝；Node 与宿主引擎共同回放别名解码、请求模型保留、规范名映射、
无映射/错误映射拒绝。固定 `.335` 宿主完整路由测试覆盖别名按次及用量结算、钱包/令牌
预扣退款、令牌模型权限、错误插件隔离及旧版本回退。所有推理请求使用本机模拟上游。

## 验证结果

- 旧 0.2.1 的 8 项别名测试中 7 项失败，准确复现模型在映射前被拒绝；新版本 118 项
  Node 协议测试通过，其中 117 个 fixture 也通过实际宿主 JS 引擎回放。
- 未修改的 `.335` 兼容宿主完整路由验证通过：规范名与别名分别覆盖按次/表达式两种
  计费方式、实际用量结算、失败退款、版本切换与插件隔离。别名价格配置仅包含别名，
  成功记录保留客户端原名与映射后模型。
- 令牌只允许规范名时不能请求别名；无映射或错误映射不会调用供应商，余额保持不变。
- 主站只读确认的 0.2.1 源码 hash 与本地基线一致；渠道已设置正确别名映射和按次价格。
  测试全部使用模拟上游，没有读取用户密钥、修改生产价格或执行真实收费推理。
- 尚未安装或激活到生产，不将本地结果视为线上验收。
