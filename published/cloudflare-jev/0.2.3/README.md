# Cloudflare Jev 任务插件 0.2.3

## 问题与方案

0.2.2 的成功结果含 `usage.input_tokens` 和 `usage.output_tokens`，但完成用量 Hook
只向宿主报告输入数量。0.2.3 在 `usageSchema` 声明两种 token 用量，
`extractUsageOnComplete` 返回经过相同边界校验的输入和输出数量，供宿主记录日志。

预估仍只报告 `input_tokens: 32000`，`billing_ratios` 返回 `null`，
用量事实不会变为按次计费乘数。原有按输入 token 的表达式不增加输出费用；
按次价格保持不变。本版本不修改用户定价。

## 配置、安全边界与兼容

- 客户端入口仍为 `POST /v1/systemone`，规范模型与别名沿用
  [0.2.2 配置说明](../0.2.2/README.md)。
- 输入用量必须为 `0～32000` 的整数，输出用量必须为 `0～2147483647` 的整数；
  缺失或无效用量仍使请求失败，不把未知用量伪造为零。
- 兼容 `.335` 宿主的调用及按次、输入用量表达式计费。
  **完整输入/输出 token 日志还需要升级包含任务插件用量日志修复的宿主；
  只升级插件不能修复 `.335` 的日志展示。**
- 市场安装后须激活 0.2.3。旧版源码、路径与哈希保持不变，可重新激活旧版回退。
- 成功结果仍不持久保存，日志只记录用量与账务信息，不新增用户请求或答案的存储。

## 验证计划

先在 0.2.2 复现完成 Hook 丢弃输出数量，再验证新版本保留输入、输出及显式零值。
Node 与真实宿主 JS 引擎回放同一组 fixture；固定 `.335` 宿主验证规范名与别名的
按次、表达式计费、退款及路由兼容。所有推理请求仅使用本机模拟上游。

## 验证结果

- 在旧版 0.2.2 上，5 项完成用量测试因丢失 `output_tokens` 失败，包含现场脱敏
  `486` 输入 / `70` 输出和显式零值；新版本 123 项 Node 协议测试通过。
- 输出用量的解析及完成 Hook 均接受 `2147483647`、拒绝 `2147483648`，
  超界拒绝测试先在修复前失败再转绿，避免宿主饱和转换掩盖原始超界用量。
- 固定 `.335` 兼容宿主的真实 JS 引擎 fixture 回放及完整路由测试通过，覆盖规范名
  与别名的按次、输入用量表达式计费；返回输出用量不会增加这些配置下的收费。
- 修复宿主开启 `CLOUDFLARE_JEV_EXPECT_TOKEN_LOGS=1` 后运行
  `node scripts/verify-cloudflare-host.mjs <修复宿主目录>`，规范名与别名在按次、
  表达式两种配置下的输入/输出日志断言全部通过。同一断言在旧 .335 上准确复现 0/0。
- 仅验证本地模拟上游，没有执行真实付费请求、生产安装或激活。
