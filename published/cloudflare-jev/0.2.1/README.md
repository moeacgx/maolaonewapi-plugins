# Cloudflare Jev 任务插件 0.2.1

## 问题与修复范围

0.2.0 只接受模型直接结果及 `success/result` 单层包裹。
真实 Cloudflare 统一接口返回的是 `success/result` 外层内再包一层
`{state:"Completed",result:{model,answers,usage},gatewayMetadata:{...}}`。
旧解析器把该状态层误当成模型结果，在读取 `model` 时抛出“响应缺少模型”，
宿主对客户端显示为 HTTP 502 / `Task request failed`，日志为 `plugin_submit_response_failed`。

0.2.1 识别这层明确的 `Completed` 结果，随后执行原有完整答案与用量校验。
不递归解包任意 `result`，不把运行中、失败、取消或未知状态当作成功，
不跳过外层失败标志或错误集合，不回传 `gatewayMetadata`。
解析后的用量仍来自模型结果中的 `usage.input_tokens`，不会按缺失用量免费成功。

## 升级与兼容

- 插件 key `cloudflare-jev`、模型 `typesafe/jev`、客户端 `POST /v1/systemone` 保持不变。
- Cloudflare 上游 `/client/v4/accounts/<ACCOUNT_ID>/ai/run` 与请求转换不变。
- 安装并激活 0.2.1 才会切换解析器；多节点应刷新各节点插件注册表。
- 无需升级兼容 `.335` 宿主，无数据库迁移、渠道密钥或价格修改。
- 已发布 0.1.0/0.2.0 源码及 hash 不可变，保留市场历史版本；回退 0.2.0 不改客户端路径，
  但会重新遇到 `Completed` 包裹解析失败。
- 账户授权、Cloudflare 余额、站点计费与解析兼容是独立条件；修复不代替供应商账户配置。

配置、请求示例与计费方式见 [0.2.0 文档](../0.2.0/README.md)。

## 验证计划

先将用户提供的真实响应结构做无账户标识的测试夹具，复现 0.2.0 的解析失败。
在 Node 与真实宿主 JS 引擎回放成功包裹、零值、不完整包裹、非完成状态、失败标志、
畸形用量和畸形答案；通过 `.335` 宿主 TokenAuth、SQLite、模拟 HTTP 上游验证统一路径、
成功响应、按次及用量计费、失败退款与版本隔离。单次 Go 测试超时 60 秒。
本轮测试全为离线及本机模拟，不使用用户密钥，不重复调用真实收费接口。

## 已执行结果

- 用现场结构回放 0.2.0，准确复现“响应缺少模型”；同一夹具在 0.2.1 成功。
- Node 协议及索引测试 111 项通过，其中 109 个协议 fixture 同时经实际宿主 JS 引擎回放通过。
- `.335` 兼容宿主的 30 个完整链路场景通过，覆盖按次和表达式两种计费模式。
- 现场结果还原出 `jev-1.13.0`、三个问题答案、输入 486 / 输出 70，不回传网关元数据。
- 在测试 `QuotaPerUnit=500000`、输入售价 $0.042/百万 token 下，预留 672 quota、实际结算 10 quota；
  独立按次 $0.01 的测试结算 5000 quota。这些数字仅为确定性测试数据，不是供应商报价。
- 对非完成状态、畸形包裹、错误标志、答案缺失及用量缺失继续拒绝；宿主完整链路验证失败退款、
  不重试与不保存成功结果。未修改生产价格或执行线上推理。
- 本地 Jev Lab 同步支持该包裹，33 个响应样例、40 次本机模拟请求通过浏览器验证，
  正确显示判断 93.0%、选择 billing、评分 1.2、输入 486 / 输出 70。

远端 CI 和修复版线上验收以对应 PR、安装激活及实际请求结果为准，不把离线通过当作已部署。
